# Phase 2 corporate design review

Base: `f970e7c4e210f339c8c7af2104ea98546ad6b514`.
Branch: `codex/whitepact-global-website-phase2`.
Scope: public website, editorial components, generated public assets and website tests. No product/runtime semantics or production infrastructure changes.

## Direction and hero decision

**REPLACE in the primary corporate journey.** The mechanical head was decorative: its appearance did not explain authority, grant scope or guarded admission. The replacement is semantic HTML describing agent intent → independent evaluation → supported execution, with denial, approval and UNKNOWN explicitly distinct. It is labeled conceptual, not live telemetry. Original assets/source remain; no historical resources are retired.

The existing near-black/red identity and Manrope/Sora/IBM Plex family concept are retained. Red marks the boundary and meaningful action; technical monospace is limited to category/state/code. No new theme, animation library, generated imagery, fake screenshots or customer proof.

## Hierarchy and narrative

The hero says what WhitePact does, where it sits and what is not sufficient authority. Docs and GitHub precede hosted signup. The unchanged doctrine follows, then authentication/intent/policy/authority/approval/grant/evidence distinctions. The control chain, labeled simulation, bounded grant lifecycle, MCP, evidence, enterprise evaluation and operating models answer separate questions. Duplicate identity/revocation panels were removed.

Product controls use native disclosures with problem, behavior, practical benefit and boundary. The architecture map preserves the complete conceptual order, split across control, execution, evidence and revocation layers. It explicitly qualifies isolation, trusted same-process code, alternative paths, dependency failure and external-effect uncertainty.

## Developer and enterprise journeys

Docs have anchored navigation, prerequisites, pinned setup, current API/MCP/source-client examples, clipboard fallback and result handling. Concepts use progressive disclosure so the quickstart is not buried beneath eight introductory cards. No fictional npm distribution or SDK evidence-detail endpoint is advertised. Source contracts remain pinned to the reviewed product baseline, not a claim of stable multi-version documentation.

Enterprise presents a deployment-evaluation checklist, not paid-plan-derived authority or certification. Trust keeps each control's status, scope, pinned evidence and limitation. About identifies founder-led development without invented scale. Contact uses only the actual project contact and coordinated disclosure path; no fake department or SLA.

## Visual system and responsive intent

Incremental corporate-only CSS adjusts heading scale, paragraph line length, section rhythm, borders, diagram spacing, disclosure focus and footer groups. Existing console and Sovereign product semantics are untouched. Corporate max widths prevent stretched copy at 1920px. On narrow screens the diagram stacks, architecture becomes one column, on-page indexes use two columns, code scrolls within its region, and documentation navigation moves above content.

Native lists/definitions/disclosures provide textual graph equivalents. Critical information requires no motion. Performance and browser evidence are recorded separately; screenshots are local review artifacts outside the repository. Automated axe is not WCAG certification, and visual inspection is not a measured five-second user study.

## Review boundaries

No layout/artwork from benchmark companies was copied. No production host, commercial availability, external assurance, customer logos or uptime is inferred from local browser results. Owner acceptance and production delivery identity remain separate gates.
