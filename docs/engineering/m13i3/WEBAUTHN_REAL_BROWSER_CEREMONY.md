# Actual browser WebAuthn ceremony

Harness: `scripts/engineering/m13i3_browser_journey.py`; browser implementation: `tests/js/m13i3-real-webauthn.mjs`. It creates/migrates disposable PostgreSQL, runs real application/mail HTTP servers and starts a fresh Chromium context. Signup, backend-generated local verification mail, verification, password login, organization and owner session are genuine browser HTTP requests. This is not a full visual form-usability test.

The CDP authenticator starts empty. No `WebAuthn.addCredential`, response fixture, request rewrite, private-key injection, fabricated authenticator bytes or disabled signature check is used. A network guard aborts non-application browser requests; application requests continue unmodified to the real server. The private local mail receipt is fetched separately over authenticated loopback HTTP. `navigator.credentials.create` supplies client data and authenticator data. The code also implements `navigator.credentials.get` and server assertion submission, but these later stages are not attempted after registration is refused.

On exact Argon implementation `e6af2f8...` with test-only review child `ce41f20487a5e4c4ac6d6932bb665ac1b2c9b667`, the actual run confirms browser-generated registration and matching local RP/origin. The legitimate ADD_PASSKEY step-up request returns200; registration finish returns403 `AUTHENTICATION_ASSURANCE_TOO_LOW`. No passkey registration/assertion verification or customer authority is claimed. On unchanged product enforcement the earlier RP/origin mismatch remains a separate blocker.

`--report` writes redacted structured evidence independent of application stdout logs. Reports include source/harness Git identity, each attempted endpoint/status, first blocker, unexecuted stages and cleanup. Passwords, verification tokens, grants, session tokens, signatures and response bodies are not emitted. Seven pure evidence-invariant tests passed; they validate evidence handling, not authentication.

Emulation proves bounded browser API/RP/origin/credential-generation behavior. It does not prove physical possession, biometric/user-presence security, hardware key protection or hardware interoperability. Server verification must succeed before the ceremony can qualify. Official references: [CDP WebAuthn](https://chromedevtools.github.io/devtools-protocol/tot/WebAuthn/), [Playwright CDPSession](https://playwright.dev/docs/api/class-cdpsession).
