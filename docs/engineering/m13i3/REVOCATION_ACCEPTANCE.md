# Revocation and containment acceptance

Original and extended suites are preserved, including revocation kernel, in-flight revocation, delegated revocation verification, DNS/egress boundary, independent cross-worker tracking, injected durable-crash and verified containment tests. Fresh I3 execution is reported only once completed; pending is not pass.

These suites include controlled scheduling/registries, seeded service identities, injected cancellation and callback acknowledgements. They do not prove actual distributed worker crash/restart, physical containment or the fresh customer's authority lineage. Native Linux/container jobs independently enforce no-skip guards; Darwin exclusions are not counted as native passes.

Application disable atomicity, concurrent registration, existing-grant invalidation across the new application contract and the full real customer's post-revocation denial remain BLOCKED until Argon's exact implementation qualifies. Session logout cleanup is not authority revocation. UNKNOWN/UNRESOLVED outcomes must not be relabeled successful containment. No original reproducer or enforcement source is changed.
