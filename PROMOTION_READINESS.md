# WhitePact public promotion readiness

WhitePact is ready for measured technical promotion, with public claims kept inside verified boundaries.

## Current launch gate

Before broad launch posts such as Show HN or Product Hunt, reconcile the MCP tool-count drift tracked in issue #57. Public surfaces currently disagree between 27 and 30 tools. Do not choose the larger number for marketing purposes; tie the advertised count to a specific release or generate it from the server's `tools/list` result.

## Safe claims

- WhitePact is an open-source AI governance and runtime-authority platform.
- v1.2.6 is the current released version.
- The repository provides deterministic five-way governance decisions: ALLOW, ALLOW_WITH_REDACTION, REQUIRE_APPROVAL, DENY, and QUARANTINE.
- The project publishes release artifacts including wheel, source distribution, SBOM, and checksums.
- OpenSSF Best Practices status must be described only at the officially awarded level shown by the OpenSSF project page.
- Technical Gold evidence may be discussed as evidence, but not presented as an awarded Gold badge until officially awarded.

## Do not claim without independent evidence

- enterprise adoption
- MNC interest
- customers or partnerships
- production deployments by third parties
- independent endorsements or reviews
- fabricated users, stars, forks, contributors, downloads, or testimonials
- OpenSSF Gold certification before official award
- a specific MCP tool count that is not tied to a reproducible release/runtime result

## Public contribution routes

Use existing issues rather than promotional spam:

- #56 — independent security/architecture review of the runtime-authority model
- #57 — MCP client verification and public tool-count reconciliation
- #58 — design-partner call for a real autonomous-agent workflow, with no implied endorsement

## Launch sequence

1. Resolve #57 and make README/package/listing counts consistent.
2. Verify the release/security/quickstart links from a clean install.
3. Prepare a technical Show HN submission focused on the problem, implementation, and reproducible demo.
4. Submit to reputable MCP/open-source directories that explicitly allow project submissions.
5. Use Product Hunt only after the technical launch surface is consistent.
6. Track genuine stars, forks, contributors, issues, external mentions, package activity, directory visibility, and design-partner interest.

This document is a claim-boundary checklist, not a certification or adoption statement.
