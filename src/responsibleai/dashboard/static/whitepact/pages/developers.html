Connect the action boundary

Start a local evaluation, connect a supported API or MCP action, and handle denial, approval and uncertainty without turning a client response into authority.

Start with the CLI

The repository defines the whitepact CLI for product diagnostics and platform utilities. Start with whitepact --help and whitepact info. The documented Python distribution is rai-governance-platform; the product name is not the installation name. Optional commands have their own dependency requirements.

Before your first action

Use the pinned source quickstart in the docs, configure the supported runtime dependencies and obtain an organization-scoped machine credential with the required role. The selected tool must be registered and supported. Configure legitimate authority and consent in the backend before expecting an action to proceed; an API key alone is insufficient.

Python HTTP helpers

The source Python GovernanceRuntimeClient provides Bearer-authenticated calls for governed tools, approvals and evidence. Review its request and result contracts in the versioned source before integrating. Keep credentials in trusted server-side code.

TypeScript source SDK

The repository contains TypeScript governance helpers for tool calls, approvals and evidence. Review and build the source against the selected server contract. This page does not represent the source SDK as an available published npm package.

MCP and API

Use the configured Streamable HTTP /mcp endpoint or the governed API tool-call interface on your verified host. These integration interfaces require authentication and a registered supported tool. An anonymous documentation page does not grant access to protected integration references or API operations.

Tool discovery is not tool authority

An MCP-capable agent may discover a tool without being authorized to invoke it. Route the MCP request through the configured WhitePact authority boundary before the supported tool executes. WhitePact does not automatically govern unrelated MCP servers or a client's direct tool calls.

Handle results deliberately

An approval-required request has not executed; denial grants no authority. Preserve UNKNOWN and reconcile the downstream system before any retry. Use authenticated evidence lookup within the signed-in organization and review the generated reference for exact schemas.

Resolve, execute, inspect and revoke

Use the documented approval resolution and execution interfaces only when the current backend permits them; resolution is not a client-created grant. Inspect the supported evidence list or signed-in evidence detail. After credential or authority revocation, subsequent supported checks must use current state. Reconcile UNKNOWN before retrying: neither revocation nor a retry can undo a completed external effect.

Verify before production

Confirm the host, credential scope, registered tools, service/runtime enforcement and operational configuration. The examples and source prove implementation contracts, not that a particular hosted deployment is ready or that every integration path enforces every control.
