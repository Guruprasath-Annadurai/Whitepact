Controls with a defined scope

Evaluate WhitePact security through its supported control paths, documented evidence and explicit limitations.

Protect the authorization path

Human sessions and machine credentials have distinct trust paths. Authentication alone does not authorize an action. Keep API credentials server-side and validate organization scope and lifecycle behavior in the configured backend.

Constrain execution and replay

Review grant scope, expiry, approval consumption and current authorization checks in the selected runtime contract. Do not replay an uncertain operation. Revocation affects subsequent supported checks and cannot undo a completed external effect.

Tenant boundaries are deployment requirements

Authenticated access must remain organization-scoped at the server. Browser-supplied identifiers and client-side controls are not authorization. Validate the supported credential, storage and resource-access paths in the actual installation rather than inferring isolation from the website.

Failure, telemetry and incident handling

A denied or unavailable authorization check is not permission for a direct fallback. Review supported health and telemetry surfaces without treating them as security authority. Establish incident ownership, evidence retention and downstream reconciliation before operating consequential actions; this page does not promise a staffed response team or an SLA.

Tamper evidence, not an absolute ledger

Hash-chained records support detection of changes within documented verifier and storage boundaries. They are not an immutable ledger against a fully compromised database. Evidence alone does not establish authority or prove a downstream effect.

Operators remain in the boundary

Deployment security includes trusted code, infrastructure, secrets, network paths and storage. WhitePact does not claim universal enforcement over arbitrary plugins, bypass paths or compromised operators. Review the integration's trusted computing boundary before relying on a control.

Assurance status

Implemented controls, production validation and external certification are separate facts. WhitePact does not currently claim SOC 2 or ISO 27001 certification, an independent commercial penetration test or an uptime guarantee. The Trust Center records the published assurance scope.

Report a vulnerability

Use the repository's coordinated disclosure policy and its published security contact for suspected vulnerabilities. Follow the policy's current reporting instructions and avoid including secrets in public issues.
