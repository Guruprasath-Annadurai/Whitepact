Authority before action

WhitePact evaluates whether an AI-agent action is authorized before consequential execution on supported, configured paths. Explore the control, the benefit and the boundary.

Evaluate a declared action

Bring identity, delegated authority, purpose and applicable policy together before a supported action proceeds. Authentication identifies a principal; it does not establish permission to perform an action.

Turn judgment into a guarded action

Evaluation output is not enforcement by itself. Consequential effects must pass through the configured guarded execution boundary. Scoped, time-bound grants apply where implemented; approval does not create authority in the browser.

Keep approval explicit

An approval-required result means the action has not executed. Authorized approvers resolve the request through the service, and the supported execution path checks current authorization before proceeding. A denied action remains denied.

Understand the outcome

Evidence records support investigation and audit. They are not authority and do not independently prove an external effect. UNKNOWN must remain UNKNOWN: reconcile the external system before any retry, even after an HTTP success or redirect.

A boundary you must configure

WhitePact does not control arbitrary code, direct tool calls outside its integration paths or compromised infrastructure. Identify the trusted computing boundary and validate the deployed configuration for each integration. Source implementation, public deployment and commercial availability are separate facts.
